## 🏗️ Архитектура: скелет функционального ядра

Этот репозиторий создан с учетом удобства обслуживания и производительности с использованием модульного скелета.

### **Основные модули (`lib/core`)**
Универсальные утилиты извлекаются в скрытые базовые пакеты для уменьшения дублирования:
- **`core.base`**: Фундаментальная логика, такая как `ConfigStore` (постоянство JSON).
- **`core.peripherals`**: Безопасное обнаружение и упаковка периферийных устройств (`PeripheralScanner`).
- **`core.network`**: Стандартизированные протоколы связи (`RednetProtocol`).
- **`core.redstone`**: помощники взаимодействия Redstone (`RedstoneController`).
- **`core.ui`**: повторно используемые компоненты пользовательского интерфейса (`ButtonGrid`).
- **`core.inventory`**: стандартизированная обработка запасов (`InventoryAdapter`, `ItemMatcher`).
- **`core.recipes`**: хранилище рецептов в формате JSON («RecipeStore»).

### **Разрешение зависимостей**
Установщик автоматически рекурсивно разрешает зависимости. Например, установка create_crafter автоматически загрузит необходимые модули core.inventory и core.redstone. Файлы приложений размещаются в корневом каталоге, а основные библиотеки хранятся в иерархии `lib/core/` (доступ к которой осуществляется через измененные пути к пакетам в `startup.lua`).

## 🛠️ Рекомендации по разработке

### **Добавление нового приложения**
1. Создайте папку приложения (например, «Мое новое приложение»).
2. Реализуйте свою логику, используя существующие модули lib/core.
3. Зарегистрируйте свое приложение в файле manifest.lua.
4. Добавьте зависимости, если вы используете основные модули.

### **Добавление основного модуля**
1. Поместите модуль в `lib/core/<category>/ModuleName.lua`.
2. Зарегистрируйте его как пакет `hidden = true` в `manifest.lua`.

## ⚖️ Безопасность и правила

Весь код в этом репозитории регулируется **[AGENTS.md](../../../AGENTS.md)**.
- **Строгий режим**: сценарии приложений и входные файлы используют строгую среду для предотвращения случайных глобальных переменных (основные библиотеки в настоящее время обходят это, чтобы уменьшить шаблонность локализации).
- **Без удаления**: программа установки никогда не удаляет существующие пользовательские файлы (за исключением очистки собственных временных файлов, таких как `manifest.lua` и `install.lua`, после завершения или замены старых версий во время обновления).
- **Кэш состояния установки**: установщик создает скрытый файл `.install_state.json`, чтобы запомнить, какие версии файлов были установлены. Это ускоряет будущие запуски за счет пропуска файлов, которые не были изменены (отображаются как `CACHED`). Этот файл можно безопасно удалить в любой момент — при следующей установке все просто загрузится заново.
- **Нет автоматической перезагрузки**: установщик запрашивает перед запуском входных файлов и никогда не перезагружает систему без разрешения.
- **Политика единого приложения**: на одном компьютере с расширенными возможностями поддерживается только **одно** приложение. Установка нескольких приложений на одном компьютере приведет к коллизиям файлов и перезаписыванию критически важных файлов, таких как startup.lua или Dashboard.lua.
